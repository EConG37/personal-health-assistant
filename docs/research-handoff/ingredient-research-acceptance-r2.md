# 食材研究 r2 复验

复验日期：2026-10-31。

**结论：结构通过，数值字段的降级和单位修订有实质进展；仍需 r3 修订，不能据此批量启用自动推荐或营养累计。**

本次复验提交的实际文件、已保存的 USDA 搜索响应、指南原页及部分在线原文，没有修改原 r1/r2 数据或软件运行规则。本次仍为结构、来源和一致性验收，不是临床审核。不要求把所有缺失数据补满：如实为空可以保留，重点是消除错误对应和未验证数据的隐性使用。

## 已确认通过的改动

- 实际 r2 JSON 通过现有 v2 Schema；88食材、7目标、616评估、100形态、534指标、17规则审计，无缺失基线ID或悬空引用。
- 534指标确为142单值、2仅区间、390完全空值。按“单值或区间非空”的统一口径，数值指标共144。
- 没有发现非空数值指标仅引用 unavailable/abstract_only 来源；克/毫升声明冲突、单值与区间并填、not_found却有数值等上轮机器问题均已清零。
- USDA 80项数值与提交目录中8份原始搜索响应的对应 FDC ID、nutrient ID 和单位逐项一致。这证明摘录一致，不代表它们可以套用于不同食品或不同生熟状态。独立重试 FDC 169732 实时详情接口返回429，本轮未重新获取全部实时详情。
- 在线读取到 [AASLD 2023全文](https://pmc.ncbi.nlm.nih.gov/articles/PMC10735173/)，其减重3%～5%、通常需更大减重（>10%）以及相关饮食章节确实存在。全文补证可保留；仍有未同步更新的原则与人群限制，见下文。
- 未核实数据转存独立候选附件、撤回“可以直接进行菜品营养累计计算”的声明，方向正确。

## 必须修订

### R1：未核实数值仍留在说明文字中

对评估理由中的“能量约…kcal/100g”进行检查，共74处。其中66处在适用形态下没有非空能量指标，另6处与本轮已有数值不一致；只有2处与指标一致。这是文字层面的遗留，原有结构校验不会发现。

| 食材 | 文字仍写 | r2能量指标 |
| --- | --- | --- |
| 低脂奶 | 46 | 42 |
| 白米饭 | 116 | 130 |
| 煮面条 | 110 | 138，但对应的是鸡蛋面 |
| 燕麦 | 367 | 379 |
| 甜玉米 | 112 | 86 |
| 马铃薯 | 81 | 77，生品口径 |
| 杂粮饭 | 124，并据此作能量密度判断 | 已全部置空，无固定配方 |
| 希腊酸奶 | 59 | 已置空 |

以上数字均为数据文件的对照例子，不是新的饮食建议。具体路径和全部74处见 `acceptance-r2/content-checks.json` 的 `energy_text`。

**修订要求：**清理 rationale、conditions、notes、principles、rule_audits 等所有文本中的未核实单品数值。已有核实值也必须对应形态；不能把生品数值拿来解释熟品，不能只替换数字而保留由旧数值推导的能量密度标签。定性建议可以保留，但需要相应类别证据或明确推断。

豆干的血糖理由仍写“几乎不含碳水，对血糖无直接影响”。主库没有可支撑该绝对表述的成分与单品反应数据，应删除或改为有条件的类别级建议；“对血糖无直接影响”也不能由低碳水直接推出。

### R2：食品身份与来源条目仍不一致，涉及过敏原

| 提交形态 | 实际引用 | 必须处理 |
| --- | --- | --- |
| 生全蛋 `egg__whole_raw` | 熟鸡蛋嘌呤1，与生全蛋 USDA 营养值混在同一形态 | 拆生/熟；熟蛋嘌呤归熟形态，生蛋无依据的嘌呤留空 |
| 普通鲜面条 `noodle__boiled` | USDA 169732，Noodles, egg, enriched, cooked | 独立命名为对应鸡蛋面；不得当普通小麦鲜面成分；核对适用的过敏原。当前仅列wheat，遗漏该新增含蛋形态 |
| 玉米淀粉 `new_starch__corn` | 土豆淀粉5mg/100g | 这是不同食材，撤值或另建土豆淀粉形态；玉米淀粉留空等待自身来源 |
| 全麦面包 `bread_whole__sliced` | 面包（带皮）51mg/100g，原表未声明全麦 | 不得默认为全麦；补匹配来源或留空 |
| 烧烤/卤味混合类别 `bbq__mixed` | 羊肉串（熟）223mg/100g | 只能是该具体样本，不是所有烧烤卤味的代表值 |
| 香肠/腊肉 `sausage__processed` | 火腿罐头、午餐肉罐头94～103 | 区间来自不同产品，不能成为香肠腊肉的可核算范围；拆具体产品或留空 |
| 通用干香菇 `mushroom_dried__dried` | 金钱菇405，另一个花菇样本357只写进备注 | 缩窄身份为原样本或拆形态，不把选中的样本当所有干香菇 |

其中土豆淀粉、面包名称及数值已对照原指南印刷页12/PDF第14页，截图 `acceptance-r2/gout-p14.png`。生/熟蛋、羊肉串等可对照先前保存的PDF第17页。机器可定位清单见 `manual_review_findings`。这些问题不能仅靠加一条“美国值可能不同”或“类别参考”的备注解决，程序仍可能直接读取数值字段。

### R3：原则与旧规则审计仍有题录直接引用，未随新全文更新

仍有9处 `support: direct` 的引用定位为“题录”。其中：

- `/principles/18`：`RULE_LIVER_WEIGHT_SUGAR` 仍写“AASLD…摘要级”和旧5%/10%表述，出处仍是“指南题录”。
- `/principles/19`：`RULE_LIVER_ALCOHOL` 仍写“摘要级与国内共识一致”，但国内共识尚未补证。
- `/rule_audits/15`：`liver_goal_coverage` 仍宣称“本轮…AASLD摘要级+肥胖指南迁移适用”。
- 其他位置涉及 ACR、BMJ/JAMA、樱桃综述，详见 `automated-checks.json` 的 `direct_refs_to_catalogue`。

**修订要求：**将确实读取的正文/摘要中能支持的具体部分准确定位；没有读到的降级。不能只更新 sources.access 和88条食材评估，却保留旧的原则和规则审计。解释“直接支持原则”与“由原则推断单品”的区别，不能以602条含direct引用等同于602条单品结论有直接证据。

### R4：份量仍有跨目标迁移，人群边界未保留

- 9种水果的 glucose 评估写每日水果总量200～350g，但所引2024高血糖指导原则第五条仅要求选低糖/低GI水果并计入总能量，没有给出该数值。200～350g可在本地痛风指南第二条找到，不能自动迁移为糖尿病目标的确定份量。糖尿病对应评估需补其自身依据和条件，补不到则删除这个确定数值。已查阅扫描原页印刷页18（`downloads/glucose-principles-2024-f2.png`）。
- `new_salt` 的 liver 为 `not_specifically_addressed`，却仍填“每日≤5g”，引用只有“本指南未规定单品”的推断。应清空，或明确由哪个已核实且适用的通用/合并疾病规则提供；不能冒充AASLD的限盐条款。
- 肝目标多处把热量缺口概括为全部成人的基础要求。AASLD原文将该要求限定于超重/肥胖人群，并单独说明瘦型患者可能不适合推荐减重。需在 population/conditions/principles 中保留该边界，不能只写“脂肪肝成人”。原文见 [AASLD全文的瘦型NAFLD与生活方式章节](https://pmc.ncbi.nlm.nih.gov/articles/PMC10735173/)。
- `protein_08_10` 的 proposed_text 仍把肥胖指南蛋白15%～20%、三餐3:4:3迁移为一般成人替换规则；上轮已要求保留适用人群。未补一般成人依据前，不能作为全体用户默认规则。

## 需要更正的检索和报告表述

1. **“GI网站没有公开检索入口”不成立。** 本次直接打开 [GI Search](https://glycemicindex.com/gi-search/)，可读取带食品名称、GI、生产国家、份量、参考文献、受试者类型及测试年份的公开表格。应改写为“前轮未成功完成匹配检索”，不能据此断言不存在入口。无需强行补回19个旧值；可以留空，但缺口原因应真实。即使网站有值，也必须匹配食品/品种/制法，不能随便取一行填通用食品。
2. **“8种USDA实测值”表述过强。** 当前有SR Legacy和FNDDS两类。USDA说明SR Legacy也包含计算、文献来源，FNDDS是汇编数据库；不能统一宣称每项本轮实测。改为“USDA对应条目报告值”，保留数据类型和能查到的逐营养素来源属性。[USDA数据类型说明](https://fdc.nal.usda.gov/data-documentation/)
3. AASLD source.url 仍只指向无摘要题录，建议补实际全文URL和相关章节，修正 publication_date。当前本地 `aasld2023.txt/xml` 各151字节，是接口500错误响应，不能作为已下载全文附件。在线正文可达，不要求为修订而伪造本地全文。
4. 更正“全部撤下”“仅留明文份量”“题录问题清零”等过度完成声明；以实际文件为准。保留390项空值并不构成真实性失败，也不要求补齐后才能做真实菜品名称与配方收集。
