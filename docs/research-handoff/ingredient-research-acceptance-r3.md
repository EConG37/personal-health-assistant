日期：2026-10-31。

- AASLD全文URL、USDA条目报告值的措辞与GI公开入口更正可保留。来源类型差异可对照[USDA官方说明](https://fdc.nal.usda.gov/data-documentation/)；肝目标的人群边界可对照[AASLD原文](https://pmc.ncbi.nlm.nih.gov/articles/PMC10735173/)。本轮不要求再次补证这些已修好的项目。

## A：5种非肉类仍套用高嘌呤肉类模板

以下 uric 评估的 rationale 完全相同，仍声称“该食材嘌呤值属第一类（≥150mg/100g）”，并建议“汆煮弃汤”；conditions还有“肉类汆煮后食用、不喝汤”。对应形态的嘌呤数值却全部为空，且部分为体积基准，不能由分类阈值反推单品含量。

| 食材 | JSON路径 |
| --- | --- |
| 啤酒 | `/foods/78/goal_assessments/uric` |
| 白酒 | `/foods/79/goal_assessments/uric` |
| 含糖饮料 | `/foods/80/goal_assessments/uric` |
| 果汁 | `/foods/81/goal_assessments/uric` |
| 蜂蜜 | `/foods/82/goal_assessments/uric` |

这不是缺少精确值那么简单：把饮品和蜂蜜套入肉类的烹调操作，本身就是模板错误。所引本地《成人高尿酸血症与痛风食养指南》印刷页6/PDF第8页还明确区分酒精影响与嘌呤含量，提到白酒嘌呤含量低但酒精度高，和这里的“白酒第一类高嘌呤”直接冲突。

**修订：**逐项按已读指南关于酒精、果糖、含糖饮品的具体条款重写限制理由、条件、烹调备注及原则ID；删除没有单品值支撑的分类断言和肉类操作。不要只修改 rationale，保留同一套错误 conditions/preparation_notes。分类表本身不能证明这5个食品均≥150mg/100g，也不能以无数值为由反向宣称它们可正常饮用。

## B：成分及份量残留仍藏在非能量文字中

本轮已修好热量值，但现有清理正则未覆盖括号、百分号、“仅”“可达”等写法。复验至少定位到15处需要删除、补证或补计算说明的文字，完整路径与当前引用见 `acceptance-r3/content-checks.json` 的 `manual_text_findings`。

| 条目与目标 | 仍在文字里的值 | 当前缺口 |
| --- | --- | --- |
| 蛋白 pressure | 钠166mg/100g | 钠指标为空；引用只有富钾食物方向 |
| 牡蛎 pressure | 钠约270mg/100g | 钠指标为空，未补对应单品成分 |
| 芹菜 pressure | 钠约80mg/100g | 同上 |
| 鳕鱼 lipids | 脂肪仅0.5g/100g | 脂肪指标为空，且评估同时包含生/烤形态 |
| 橄榄油 lipids | SFA约14% | 饱和脂肪单品数值未补证；植物油原则不证明百分比 |
| 蜂蜜 glucose | 约80%为糖 | 对应成分为空；高GI举例不证明糖百分比 |
| 可乐 general | 500ml已超50g糖 | 无对应产品、标签或已核成分 |
| 普通面条 pressure | 一碗含盐2g以上 | 无一碗重量、产品与钠数据 |
| 西瓜 glucose | 单次≤200g时GL有限 | GI和可利用碳水均未核，缺计算依据；份量字段清空不能清除文字中的用量判断 |
| 核桃/杏仁 lipids（2处） | 每日10～15g | 引用仅为“提高不饱和脂肪比例”，不能直接推出单品份量 |
| 食盐 glucose/lipids（2处） | 每日≤5g | 份量字段已空，rationale仍直接保留跨目标上限，未明确通用规则依据及迁移边界 |
| 啤酒 pressure | 500ml已接近男性酒精上限 | 缺对应酒精度及换算；酒精克数限制不自动等于某个体积 |
| 白酒 pressure | 50度白酒约62ml | 需给计算口径、公式、输入和密度来源，或删除这条体积换算 |

这些例子不是声称其中所有数字必然错误，而是它们仍被当作确定的单品数值或份量使用，却不具备本次声称的核实依据。

**修订：**先把这些具体数值和由其推导的结论撤下；已有类别原则的可保留定性结论，并标清推断。要保留数字，则补齐具体样本/产品/形态的实际来源；计算需有输入出处、公式和适用条件。不得通过把数字移进括号、notes或rationale来绕过空值约束。

继续检查全部文本层，但不要把已核实的嘌呤表值、已核实的8处热量、指南的人群总量和明确区分的反例说明一概删除。需要的是语义核对，不是清空所有数字。

## C：清理能量数值时引入了自动放宽标签的回归

相较r2，有9个weight标签从limit变为compatible_under_conditions：全麦面包、燕麦、干紫菜、沙丁鱼、凤尾鱼、小鱼干、干香菇、食盐、玉米淀粉。

研究者 `build/r3_text.py` 的默认分支对没有能量值且不在特定类别名单的食品统一输出 compatible_under_conditions，并只附“计入每日总能量”。当前共有68条weight评估在无能量指标时使用这个标签。这不表示68条都应该限制，也不表示缺能量就必须标证据不足；问题在于，**标签必须来自独立、可解释的类别依据，不能由能量缺失自动放宽。**

明确例子：`/foods/85/goal_assessments/weight` 食盐原来为limit，现在为compatible，conditions只写“计入每日总能量”，portion_guidance为null。它仍引用少油少糖少加工及控制油盐糖的肥胖指南，却丢失了原有限盐的判断逻辑。食盐应如何限量不能由“未获得食盐能量值”决定。

**修订：**停止把 missing energy 当作 compatible 的默认理由。逐项审核9个变动标签，给出继续限制、条件允许、未专门讨论或证据不足的独立依据。不要盲目恢复全部旧limit，因为旧标签同样可能缺证；也不要仅按每100g是否低于400kcal来替代食材和实际份量判断。检查其余通用模板是否覆盖了本来应保留的条件。

## 报告统计需同步更正

- “评估文字中仅剩2处数字”及“仅剩2处能量/脂肪+数字”与实际文件不符。本轮仅能量数值就有8处，且均与指标一致；还有已核嘌呤、指南总量及上述未核实成分。应报告检查的准确范围及匹配口径。
- “份量仅16条”仅是 `portion_guidance !== null` 的字段计数，不能等同于文本中只有16条份量建议或所有用量均有同目标证据。
- “无不同食品套值”可针对修好的7项陈述；“文字不再借用任何未核实数字”目前不成立。
