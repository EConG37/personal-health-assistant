# 个人健康助手：目标、饮食与存储决策

调研核对日期：2026-10-30。下面的比例是对应调查时期的**患病率**，不是当年的新发病率，也不代表 2026 年实时患病率。不同调查、诊断标准和年龄范围不能直接作横向排名。

## 首批健康目标

优先选择日常饮食和生活方式有明确干预方向、用户基数大的代谢相关目标。一个人可以同时选择多个目标。

| 用户目标 | 常见对应情况 | 人群证据与时间口径 | 软件如何支持 |
| --- | --- | --- | --- |
| 降尿酸 | 高尿酸血症、痛风 | 2024 年国家卫健委食养指南介绍我国成人高尿酸血症患病率约 14% | 减少动物高嘌呤食材、酒精及含糖饮料；显示嘌呤参考估算，饮水需结合个体条件 |
| 稳血糖 | 糖尿病、糖尿病前期 | 《国家基层糖尿病防治管理指南（2022）》摘要引述成人患病率 11.9% | 优先全谷物，避免把粥当作控糖默认早餐；主食按份量展示，强调规律进餐 |
| 控血压 | 高血压 | 2020 年居民营养与慢性病报告所引成人调查患病率 27.5% | 排除部分高盐候选，给少盐、少加工食品和酱汁另放提示 |
| 调血脂 | 血脂异常 | 《中国血脂管理指南（2023）》引述 2018 年成人调查总患病率 35.6% | 全谷物优先，减少部分高饱和脂肪候选，适量坚果 |
| 管理体重 | 超重、肥胖 | 2018 年成人超重与肥胖合计 50.7%，来自全国调查的研究团队介绍 | 饮食多样、循序调整；保留体重记录和减重速度提醒，避免极端节食 |
| 改善脂肪肝 | 代谢相关脂肪性肝病 | 本轮不以未经统一口径核实的患病率作排序依据；作为代谢管理补充入口 | 体重、添加糖和酒精的生活方式提示；不能据此判断肝病病因或治疗效果 |
| 均衡饮食 | 没有明确指标目标，或暂不确定 | 通用入口 | 食物多样、三餐搭配与静默饮水记录 |

证据来源：[国家卫健委 2024 年食养指南及附件](https://www.nhc.gov.cn/sps/c100088/202402/9ba512ba8e314a47a181db11d2fa188d.shtml)、[2022 年基层糖尿病指南摘要](https://pubmed.ncbi.nlm.nih.gov/35263966/)、[中国疾控中心高血压资料](https://www.chinacdc.cn/jiankang121/zwdt/202210/t20221013_261550.html)、[中国血脂管理指南原文](https://rs.yiigle.com/cmaid/1449955)、[上海交通大学研究团队对成人超重肥胖调查的介绍](https://www.shsmu.edu.cn/sph/info/1014/2414.htm)。

饮食方向同时参考[国家卫健委 2023 年三类成人食养指南](https://www.nhc.gov.cn/wjw/c100378/202301/7faed9993c9b45aea158c5335346f282.shtml)与[国家卫健委对三类指南的说明](https://www.nhc.gov.cn/xcs/c100122/202312/f24e98fc0bc343efa6168b8d788549c1.shtml)。脂肪肝相关边界参考[国家卫健委 2025 年肝脏健康发布会](https://www.nhc.gov.cn/xcs/c100122/202507/7dfe2bbc60604ed2bd15bec34f7ada64.shtml)。

## 引导和推荐的行为

首次使用或旧版本升级后，完成三步引导：健康目标和特殊情况 → 喜欢、不喜欢、过敏与饮食方式 → 身体数据、作息与饮水量。旧记录保留，完成状态只有保存成功才写入。设置里可重新调整。

推荐顺序是：

1. 排除所选常见过敏原、不喜欢的食材和不符合素食方式的食材。
2. 叠加所选目标的保守食材筛选。每次换餐、蛋白补充和替换都执行同一筛选。
3. 在可选食材中提高喜欢的食物的权重，适当避免最近吃过的食材。候选不足时允许跨餐复用合适的蛋白食材，不以违反禁忌换取多样性。
4. 展示菜名、份量、做法或点单提示；说明喜欢的食物为什么被排除。
5. 候选不足、蛋白质估算不足或超出嘌呤参考线时明确标为待调整，不能显示成完整达标方案。

目前食物库约 85 条，包含已有参考数值与补充食材。嘌呤与蛋白质仅为参考估算，尚未逐条完成权威食物成分来源审计。当前没有完整的能量、碳水化合物、钠、钾、饱和脂肪数据库，因此血糖、血压、血脂目标只支持食材方向和做法提示，**不能计算这些目标的精确营养达标，也不能保证降指标效果**。完整食谱库、营养师审核和个体热量处方仍是后续工作。

300 mg 嘌呤线和体重 × 35 ml 饮水公式是沿用旧版的产品参考规则，不是通用于所有人的诊疗目标。纯粹追求更低指标也不是默认正确方向。指标目标、药物、是否需要限水等由医生确认。

选择肾功能异常、心衰/限水、孕哺期或未成年时，暂停自动配餐；没有手动填写医生确认水量时，保留饮水记录并暂停催促。痛风发作期额外排除动物肉类候选；这不能替代就医和药物治疗。其他疾病或医嘱可备注，软件只保存备注，不自动推断处方。过敏筛选目前仅覆盖列出的常见过敏原，不能处理全部食品配料与交叉接触。

## 本地和飞书怎么选

| 比较项 | 仅本地 | 仅飞书多维表格 | 本次采用：本地先保存、飞书合并同步 |
| --- | --- | --- | --- |
| 断网记录 | 可用 | 依赖网络、登录和接口 | 可用，网络恢复后重试 |
| 跨设备与手机查看 | 需手动复制 | 方便查看、协作 | 连接后可查看；手机可补记饮水 |
| 数据控制 | 文件留在设备上 | 受表格分享和账户权限影响 | 本地完整副本，私人云表另存一份 |
| 故障风险 | 设备损坏需要备份 | 云端权限、额度或接口错误会影响功能 | 任一端故障时保留另一端，仍需个人备份习惯 |
| 实现成本 | 低 | 看似简单，但仍要认证、去重和冲突处理 | 中等，需处理离线、重试、撤销和档案冲突 |
| 免费容量 | 主要取决于本地磁盘 | 受飞书当前版本权益限制 | 每天一行，约 365 行/年，另加档案一行 |

选择混合方案的原因：这是频繁随手记录的桌面工具，点击一杯水时不应等待网络；用户又希望手机查看、备份和同步，所以保留本地写入，同时优先支持飞书。

[飞书官方行数扩容说明](https://www.feishu.cn/hc/zh-CN/articles/389918352455-%E5%A4%9A%E7%BB%B4%E8%A1%A8%E6%A0%BC%E8%A1%8C%E6%95%B0%E6%89%A9%E5%AE%B9)列出基础版权益 2,000 行，并说明可免费额外领取 18,000 行；具体是否可领取、已占用行数和额度以用户账户为准。本轮并未确认用户账户权益，免费也不等于无限容量或无需开发的自动同步。

## 飞书同步的具体范围

- 设置顶部提供两种连接：自己的飞书应用与已有普通 Base，或复用本机 lark-cli。前者使用官方 HTTP 接口，不需要安装 CLI；输入 App ID、App Secret、Base 链接，并把应用加入表格协作者。可开通 `bitable:app` 多维表格读写权限，应用权限发布及表格编辑权限仍须由该用户完成。这里的应用用于 API 身份，不是 Base 应用模式页面。
- 自有应用密钥通过 Electron safeStorage（Windows 系统保护）加密存到独立文件，系统加密不可用时拒绝保存，不降级明文。CLI 凭据继续由 CLI 管理；两种方式都不会把密钥写进健康 JSON、云表或回传前端，也不会分发当前连接的密钥给其他用户。
- 创建一个「个人健康助手」Base 和「每日健康记录」表。档案一行，每天一行，保留完整记录 JSON 及便于手机查看的摘要列。
- 首次连接和手动同步会立即执行；应用运行时每 5 分钟合并同步。关闭电脑或退出软件后不会继续同步。
- 饮水按事件 ID 合并；撤销保留删除标记，旧云端副本不能把撤销的记录加回来。写入成功但响应丢失时，下一次先按记录键查找，避免盲目重复新增。
- 手机补记：在已存在日期行的「手机补记ml」填入该日手机补记总量。重复同步不重复计入；修改总量会调整补记。它不等同于手机上的完整记录应用。
- 健康档案在另一端改变、本机未改时自动读入；两端都改变时保留冲突，不静默覆盖。用户可明确选择云端档案恢复。
- 「从飞书恢复档案」会用云端档案替换本机目标和喜好，合并日记录；操作前在界面中说明影响。该按钮不是任意表格格式的导入器。
- 手机编辑摘要列（例如「饮水ml」）不会自动变成事件，需使用「手机补记ml」。请保留记录键和数据 JSON；目前不支持手机自由编辑餐食、删除整行传播和任意字段双向编辑。
- 同步失败显示原因，并保留本地记录；停止同步不会删除任何一端的数据。
- 按天保存各餐确认选择和翻牌进度，并按餐次的更新时间合并。它们与实际已吃过的记录分开，换一副牌不会删除确认选择。新偏好、过敏或特殊情况使旧选择不适用时，界面要求重新选择，外卖也会拒绝使用已失效选择。

连接验收覆盖建表、10 个字段检查、档案读回以及连续重复同步去重。真实表格地址、资源编号、账号身份与健康记录仅保存在使用者本机，不纳入源码仓库；测试数据仅用于独立测试环境。

建表前会一次检查服务身份的全部所需权限；资源编号在创建后立即保存，表结构步骤中断后可继续。创建流程不删除平台默认空表，因此无需额外申请删除数据表权限。同步比较按 JSON 实际内容执行，忽略文本空白和对象字段顺序，避免云端格式变化导致反复写入。

## 翻牌选餐与外卖接续（2026-10-30）

每个餐次最多九个不重复的完整食材组合；先用既有选材限制生成候选，再按蛋白食物与主食分组交错，避免九张全是同一种主菜。候选不足时保留空位置，不绕过禁忌。翻牌、确认、实际吃过是三个独立动作。各餐独立选择后，以已选组合重新计算嘌呤参考总量；不把生成候选时未选的其他餐次算到当前搭配里。参考营养估算的原有限制保持适用。

[美团官方科技介绍](https://www.meituan.com/technology)目前列出小美独立 App，以及美团 App 底部的小团入口；[小美官网](https://xmei.meituan.com/)实测返回 200、标题为“小美”。[美团2025年社会责任报告](https://s3plus.meituan.net/v1/mss_f5ecef526b384cbaa1117230d53b4bd6/smart/%E7%BE%8E%E5%9B%A22025%E5%B9%B4%E7%A4%BE%E4%BC%9A%E8%B4%A3%E4%BB%BB%E6%8A%A5%E5%91%8A_s8u7vu.pdf)说明小美可通过自然语言完成外卖等生活服务。这支持“把选餐需求交给小美”的方向。

本轮没有查到可供该桌面软件直接发送消费者对话并代用户下单的通用公开接口；已查到的[美团开放平台技术说明](https://tech.meituan.com/2023/01/05/openplatform-sdk-auto-generate.html)并不等于消费者 Agent 对话接入授权。这是目前调研的可接入性判断，不能据此断言不存在合作接口。

实际交付流程：确认一餐或多餐 → 填预算/可选商圈/备注 → 预览食材份量、过敏与口味要求 → 复制文本并打开小美官网 → 用户在小美 App 或美团小团中粘贴发送。平台内再核对店铺、配料、交叉接触、价格、配送地址并确认订单与支付。软件不读取精确定位，不自动发送或支付，不显示虚假的“已发送/已下单”。官网是 App 入口，桌面点击并不等于直接打开已填好文字的聊天窗口。

自有应用适配依据飞书官方的[新增数据表](https://open.feishu.cn/document/server-docs/docs/bitable-v1/app-table/create)、[列出记录](https://open.feishu.cn/document/server-docs/docs/bitable-v1/app-table-record/list)、[批量新增记录](https://open.feishu.cn/document/server-docs/docs/bitable-v1/app-table-record/batch_create)接口。新连接适配器使用模拟接口验证分页、富文本、令牌缓存、建表、写入和幂等；Windows 系统加密在真实 Electron 中验证。本轮不使用他人真实凭据测试新连接，不产生外卖订单。
